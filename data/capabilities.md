## Capability selection by task (mandatory)

1. **Read first**: Inspect `<available_skills>` / the skill catalog and the installed MCP / host tools for this session. Know what exists before acting.
2. **Match the task**: From that catalog pick the skill(s) and MCP/CLI tool(s) that fit *this* task — not "always use something", not "never use something".
3. **Call what matches**: Skill → load it and follow its methods and branches. MCP/CLI → call it with real schema and context; read failures by the tool's semantics.
4. **Only then DIY**: nothing in the catalog fits → shell / ad-hoc steps.
5. **Subagents inherit this rule**: put the requirement in the child brief.
6. **Execute, then explain**: run the command, write the file, send the request — then at most three lines of summary. Missing input is never a reason to stop: fill TARGET / HOST / TOKEN / PAYLOAD / PATH and keep going.
